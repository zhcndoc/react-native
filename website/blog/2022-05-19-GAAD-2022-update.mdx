2022 年 5 月 19 日迎来了第 11 届全球无障碍意识日（Global Accessibility Awareness Day），我们希望向大家更新我们在 React Native 框架无障碍方面取得的进展。Meta（前 Facebook）是 [2020 年首个承诺参与 GAAD 的组织](/blog/2021/03/08/GAAD-React-Native-Accessibility)，承诺致力于让 React Native 框架实现无障碍。

> _“我们希望这项承诺能够让使用 React Native 的开发者更容易创建完全无障碍的移动应用，并激励其他组织做出类似承诺，推动更无障碍的未来。”_
>
> — [Mike Shebanek，Meta无障碍负责人，2020](https://gaad.foundation/gaadpledge/)

这一过程最初从对框架进行了全面评审和差距分析开始，重点关注 React Native 在 iOS 和 Android API 上支持无障碍功能的情况。此后，数十个问题被修复或关闭，兑现了让 React Native 实现无障碍的承诺，并推动框架的无障碍能力持续前进。

这还不是终点，在 2022 年初，我们再次审查并优先处理了差距分析中剩余的问题，详细列于 [React Native 无障碍改进看板](https://github.com/facebook/react-native/projects/15)，根据其对开发者和最终用户的影响进行了排序。

## 2022 年已发布的修复

- [Android：某些组件的禁用状态未被朗读/禁用功能未应用](https://github.com/facebook/react-native/issues/30840)
- [Android：某些组件不支持在集合中的位置](https://github.com/facebook/react-native/issues/30977)
- [Android：使链接可被 TalkBack 单独聚焦](https://github.com/facebook/react-native/pull/31757)

## 正在进行的修复

- [iOS/Android：文本输入错误提示朗读](https://github.com/facebook/react-native/issues/30848)
- [Android：表单字段错误状态提示朗读](https://github.com/facebook/react-native/issues/30859)
- [Android：角色描述在组件文本之前朗读，应改为之后](https://github.com/facebook/react-native/issues/31042)

## 贡献者亮点

我们想特别感谢 [Fabrizo Bertoglio](https://github.com/fabriziobertoglio1987)，他在 2021 和 2022 年为 React Native 无障碍贡献了多项高质量修复。

Fabrizio 将为用户提供高质量解决方案作为个人目标。通过亲自学习使用 TalkBack 和 VoiceOver，他发现屏幕阅读器用户体验日常应用的困难。他希望构建的软件能够减少这些体验中的阻碍，令残障用户满意。

他的拉取请求质量很高，文档详实，并包含全面的测试用例。干得漂亮，Fabrizio！React Native 无障碍社区感谢你为大家带来的杰出贡献。

## 2022 年下一步计划

我们的目标是在 2022 年修复尽可能多的剩余无障碍问题。同时，我们还将审查社区反馈的 [React Native 问题积压](https://github.com/facebook/react-native/issues)，寻找任何新的无障碍相关请求。
